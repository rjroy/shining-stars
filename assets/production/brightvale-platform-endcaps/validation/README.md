# Endcap browser lighting/toon pilot

This isolated browser harness loads `../endcaps.glb` with the repository-installed Three.js `GLTFLoader`. It leaves GLB geometry/transforms untouched and retains the imported `MeshStandardMaterial` objects/factors as baseline evidence, then assigns each original role a shared, explicitly named `MeshToonMaterial` in the harness. Body stays midnight blue; edging stays warm gold. A nearest-filtered three-step light ramp gives deliberate cel-style bands. This is a derived browser consumer treatment—not a changed/exported GLB, portable toon material, game integration, or visual approval.

Run `./validate.sh` from any directory. It uses existing Vite and Chromium executables, checks invalid binary and missing-asset paths, validates the positive production GLB, captures `audience.webp` and `twilight.webp`, and writes `report.json`. Scratch files and its own Vite process are cleaned on every exit. No install or source/export/game/config changes are made.

Both modes use the same scene, imported geometry, fit camera, three-step ramp and toon palette. Audience uses warm amber key/sky light and a left-side amber point source; Twilight uses violet key/sky light and a right-side violet point source. These are perpetual-scene mood variants, not day/night. `report.json` records baseline imported PBR properties, derived mapping, lighting, geometry/camera signatures, transfer/render statistics, loader warnings, and the absolute-error changed-pixel count between complete mode views. The check requires identical camera, geometry and mapping plus a substantial image difference. Pixel difference includes the fixed background; inspect the captures to confirm the assets themselves visibly differ.

The prior neutral-room A/B proved the loader preserved the source PBR factors and showed that a neutral reflection environment made facets more legible, but Audience and Twilight remained too similar. Its original `report.json` was replaced by the current run; the short finding is preserved here. No standalone old control/room images are retained. Current views show the harness-only toon result; parent review is still needed.

## Limits

Toon mapping intentionally replaces PBR shading and drops metallic/roughness response, reflection/environment behavior and the original BRDF appearance; imported originals remain available only as recorded baseline, not as the rendered material. The 138,388-byte GLB still has 2 glTF nodes/meshes, 4 primitives, 2 material roles, 2,568 triangles, and 14 inherited near-zero-area triangles. Geometry, source normals/material data and export remain unchanged. Renderer/timing data comes from headless Chromium/SwiftShader, not target hardware; these captures do not establish final runtime appearance or performance.
