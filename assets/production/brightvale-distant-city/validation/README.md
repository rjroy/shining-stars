# Brightvale city browser validation

Run `./validate.sh` from any directory. This isolated lane uses the repository's installed Three.js `0.186.1` GLTFLoader, Vite and Chromium; it installs nothing, writes only here plus cleaned `.scratch/`, and stops its own server on every exit. It checks invalid-GLB/missing-asset failures and the positive city export, producing `audience.webp`, `twilight.webp` and `report.json`.

The camera and city placement reproduce the README's study projection exactly: city group scale `.35`, position `(0,3.9,-55)`; 1600×900, 39.76070473° vertical FOV, camera `(0,13.89999962,15)`, X rotation `−0.1148765842`. The study's clipped spire top is intentional. The separate full-silhouette source/derivative check is already in `../comparison.webp`; this harness does not reframe or recenter the city.

Imported PBR properties are recorded before a harness-only conversion of all six existing roles into shared `MeshToonMaterial`s. The mapping retains base color, double-sided flat shading and the Window emission color/strength; it does not change/export the GLB. Audience is warm amber; Twilight is violet. Both use identical geometry, mapping and camera. The report records imported/placed counts separately, shared geometry references (not GPU instancing), decoded geometry array bytes, transfer bytes, actual frame calls/triangles, timing and software-renderer backend. None of those local measurements are GPU memory or target-device budgets.

## Current findings

Both views load all 31 nodes / 24 unique glTF meshes / 132 unique primitives / six roles without loader warnings. GLTFLoader creates 150 placed primitive meshes and retains 18 repeated geometry references; the view submits 149 renderer calls and draws 36,085 triangles after frustum culling. GLB transfer is 1,584,308 body bytes (1,584,608 browser transfer bytes); decoded geometry typed arrays are 1,373,280 bytes, with no source textures. Audience/Twilight differ by 18,141 pixels; that comparison uses a fixed identical background, so changed pixels belong to the rendered city.

Inspection of both browser captures shows clearly distinct warm and violet lighting. The central landmark/tower silhouette, roofs, arcade contour and emissive windows remain visible; there is no apparent loss of a major silhouette feature. The source/derivative `comparison.webp` independently shows matching sampled silhouettes and no visible extrusion-removal artifact at the stated distant study scale. **Recommendation: safe to submit this bounded derivative for parent review and the next production-scale slice**, not whole-city approval, final art acceptance, or game integration. Close/oblique views and device performance remain unverified.

The toon consumer mapping replaces PBR metallic/roughness and reflection response. Only the window emission is carried through as color/strength; its appearance still depends on renderer and tone mapping. Headless Chromium used ANGLE/SwiftShader, not a physical GPU. `report.json` records the exact shared six-role palette, mode lights, source PBR baseline and cross-mode camera/geometry signatures.
